## Достижения: два уровня одной сущности, не два разных типа

В контенте нет отдельного понятия "Skill" (в отличие от ранних
предположений в исходном `context.md`, где приводились примеры вроде
«Кибергигиена», «Промпт-инженерия» как будто отдельная категория —
при разборе реального контента выяснилось, что это и есть финальные
бейджи карточек). Есть только `Achievement` с флагом `is_badge`:
- обычное достижение — выдаётся на конкретном выборе внутри карточки
- финальный бейдж карточки (`is_badge=True`) — выдаётся безусловно на
  completion-узле, независимо от того, какие выборы были сделаны на
  предыдущих этапах

Иногда финальный бейдж — это **тот же самый** `Achievement`, что уже
выдавался на одном из этапов (например, карточка 1: этап 1 и финал оба
дают «Финансовая самостоятельность» — это осознанное решение дизайнера
контента, не баг; выдача идемпотентна, повторно не начисляется).
В других карточках финальный бейдж — совершенно новое достижение, не
пересекающееся с этапными (например, карточка 4: «Финансовый стратег»).

Neuro-coin (упоминался в раннем `context.md` как гипотетический тип
награды) **не встречается вообще нигде** в реальном контенте карточек —
не реализован, и не должен придумываться.

## Конверты с миссиями

Источники: `КОНВЕРТЫ_С_МИССИЯМИ.docx` (концепция всех 3 миссий) +
`миссии_2_и_3.docx` (детали миссий 2 и 3, прислан позже).

- **Миссия 1** «3D-копилка с бюджетными секторами» (сектор Финстартап
  2.0) — фото-проверка, ручное одобрение куратором.
- **Миссия 2** «Шифровальная машина Энигма-лайт» (сектор КиберЩит) —
  изначально пропущена (в `КОНВЕРТЫ_С_МИССИЯМИ.docx` только
  концептуальное описание, без конкретного шифра для проверки; владелец
  проекта подтвердил, что физический реквизит ещё не готов). После
  получения `миссии_2_и_3.docx` — реализована полностью: 4
  последовательных сообщения, шифр Цезаря со сдвигом 9 по 33-буквенному
  русскому алфавиту (сдвиг проверен программно на всех 4 парах
  шифр/ответ — совпадает). Неверный ответ не штрафует, просто не
  продвигает шаг.
- **Миссия 3** «Алгоритм навигации Робо-курьер» (сектор AI-Логика) —
  первая версия (до получения `миссии_2_и_3.docx`) содержала
  **придуманную** мной раскладку поля 5×5 и шаги, т.к. точных данных не
  было. После получения уточнения — заменена на реальные 3 маршрута
  («Базовая доставка», «Городские препятствия», «Хрупкий груз и
  оптимизация») с точными координатами препятствий и точными
  алгоритмами команд из документа. Остаётся фото-проверкой (ручное
  одобрение) — CV для автоматической проверки не реализовывался.

## Прочие пометки и плейсхолдеры (не путать с реальным контентом)

- **Цвета секторов** (`color_token`, hex-значения вроде `#2DE1C2`,
  `#FF7A2D`, `#B14EFF`) — мой выбор, т.к. исходник называет цвет только
  словесно («Неоново-бирюзовый», «Неоново-оранжевый»,
  «Неоново-фиолетовый») без конкретного hex. Заменить на значения
  дизайн-системы, когда они появятся — само название цвета (текстом)
  взято из исходника и менять не нужно.
- **Раздел грандфинала** (анимация сборки, финальный приз) — в
  `квест-задания.docx` сам раздел помечен автором как черновой
  ИИ-брейншторм («все придумал ии»), то есть не проверенный дизайн, а
  идея. Анимация/сертификат реализованы как безопасная, не
  противоречащая ничему часть; конкретный **приз** (промокод/скидка)
  сознательно НЕ выдуман — в UI честный плейсхолдер «скоро появится».
- **Content gap в карточке 3 сектора 1** («Донат или инвестиция?»,
  этап «Лутбоксы»): исходник описывает последствия только для выбора C,
  для A и B нет отдельного текста. В YAML-файле заполнено минимальным
  текстом, прямо основанным на формулировке самого варианта ответа (без
  добавления новых фактов) — см. комментарий в
  `sector1_card3.yaml`.

## Как добавлять новый контент дальше

1. Прочитать нужный раздел исходного `.docx` (конвертировать через
   `pandoc -t markdown file.docx -o file.md`, если docx больше нет в
   контексте — попросить его снова у владельца проекта).
2. Создать `backend/app/content/cards/sectorN_cardM.yaml` или
   `backend/app/content/missions/missionN_slug.yaml` по образцу уже
   существующих файлов (схема полей видна из примеров).
3. `cd backend && python -m app.content.seed` — идемпотентно, старые
   карточки не трогает, добавляет только новые.
4. Проверить живым HTTP-запросом (curl) хотя бы один полный проход, не
   полагаться только на факт успешной загрузки в БД.
5. Прогнать `python -m pytest` — особенно
   `test_full_playthrough.py`, если добавлена/изменена буква/позиция
   мастер-кода.
6. Закоммитить маленьким логичным коммитом с указанием источника в
   тексте коммита.
