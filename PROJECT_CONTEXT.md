# NeuroQuest — контекст проекта для нового чата

Репозиторий: https://github.com/KimDmitriyR/NeuroQuest.git (ветка `main`, 59+ коммитов).
Читай вместе с `CONTENT_SOURCES.md` (откуда взят каждый кусок игрового контента),
`WINDOWS_SETUP.md` (запуск на Windows) и `tools/browser-checks/README.md`
(проверки в реальном браузере).

## Что это

Образовательная квест-игра для подростков. Физические карточки с QR-кодом
запускают цифровой квест (чат с ветвящимися выборами) по трём секторам
(финансы, кибербезопасность, ИИ). Есть «конверты с миссиями» (задания в
реальном мире с подтверждением фото или шифром) и общий «мастер-код» из
12 букв, который собирается за прохождение всех карточек. Родитель
регистрируется, заводит профили детей и проверяет присланные фото.

**Состояние:** всё из исходных документов реализовано — 12 из 12 карточек,
3 из 3 миссии, авторизация родителей, юридические страницы (черновик),
адаптивный интерфейс в стиле маркетплейса. Backend: 89 тестов. Frontend:
сборка, линтер и 25-шаговый сценарий в реальном браузере проходят.

   нужен GitHub Personal Access Token (fine-grained, только этот репозиторий,
   Contents: Read and write). Токен, присланный в чат, остаётся в истории
   чата — после работы его стоит отозвать (Settings → Developer settings).
2. Прислать `PROJECT_CONTEXT.md` и `CONTENT_SOURCES.md`. Исходные `.docx`
   больше не нужны — весь текст уже перенесён в YAML и закоммичен.
3. Окружение Claude может сбрасываться между сессиями (репозиторий и
   установленные пакеты пропадают) — тогда всё ставится заново, см. раздел
   «Особенности песочницы Claude».

Python 3.14 (`C:\Python314`) с venv в `backend\venv`, PostgreSQL 17 +
pgAdmin (нативная установка, **без Docker**), Node.js. Проект лежит в
`Desktop\NQ\NeuroQuest`. Docker Desktop у владельца падает с ошибкой WSL
`ERROR_NO_SYSTEM_RESOURCES` — Docker в рабочем сценарии не используется.
Пошагово: `WINDOWS_SETUP.md` (там же — как открыть сайт на телефоне по Wi-Fi: `CORS_ALLOWED_ORIGINS` и `VITE_API_URL`). Проблемы, которые уже были решены и
записаны там: `alembic` не в PATH (нужен venv), `WinError 64` у asyncpg на
Windows (обход в `app/core/windows_compat.py`), роль/база создаются вручную
в pgAdmin, порт Vite должен быть именно 5173 (CORS).
После `git pull` обычно достаточно перезапустить backend; новых
зависимостей у frontend с последнего дизайна нет, миграций тоже.

## Архитектура

### Backend (FastAPI + SQLAlchemy async + PostgreSQL + Alembic)

Слои: `models` → `repositories` → `services` → `api`; Pydantic-схемы отдельно
от ORM. Игровой контент хранится как YAML (`app/content/cards/*.yaml` — 12
файлов, `app/content/missions/*.yaml` — 3 файла) и грузится идемпотентным
лоадером: `python -m app.content.seed` (уже загруженное пропускает, а не
обновляет — при правке текста карточки нужно пересоздать БД или править
записи руками). 12 миграций Alembic.

Модели: `ParentAccount` (email, bcrypt, `terms_accepted_at`, `terms_version`),
`Player` (ребёнок, обязателен `parent_id`), `Sector`, `Quest`/`QuestNode`/
`Choice` (граф квеста; награда за завершение карточки висит на completion-
узле), `QuestCard` (`qr_token`), `Achievement` (`is_badge`), `MasterCodeLetter`
(позиция 1–12, 1:1 с карточкой), `QuestSession`/`QuestAnswer`,
`PlayerAchievement`/`PlayerMasterCodeLetter`, `EnvelopeMission`
(`validation_type` photo|text, `validation_config` JSONB; joined-связи на
`Sector` и `Achievement`), `MissionAttempt` (`current_step` для многошаговых
шифров). Текстовая миссия поддерживает `{"steps":[{"cipher","answer"}...]}`:
неверный ответ не штрафует, шаг не засчитывается.

Авторизация: JWT (HS256, 30 дней), bcrypt. Регистрация требует
`accept_terms: true` (иначе 422), факт и версия согласия пишутся в БД;
версия документа — `app/core/legal.py::CURRENT_TERMS_VERSION`.

### Доступ: токен родителя и токен ребёнка

Два вида JWT (claim `typ`), один секрет:

- **Родитель** — `Authorization: Bearer <jwt>` (30 дней). Нужен для кабинета,
  создания детей, очереди проверки, выдачи токенов ребёнка.
- **Ребёнок** — заголовок `X-Player-Token: <jwt>` (180 дней,
  `PLAYER_TOKEN_EXPIRE_DAYS`). Привязан к ОДНОМУ игроку, живёт в ссылке
  `/?t=<token>`, которую родитель отправляет ребёнку. Родительским токеном
  не является и родительские эндпоинты не открывает.
- Отзыв: `players.token_version` попадает в токен (`ver`).
  `POST /api/players/{id}/access-token/reset` увеличивает версию — все старые
  ссылки/устройства ребёнка умирают (401 «Access link was reset»), прогресс
  сохраняется.

Игровой эндпоинт пускает вызывающего, если у него валидный токен ЭТОГО
ребёнка **или** он вошёл как родитель-владелец (`api/deps.py::PlayerAccess`).
Нет ни одного валидного токена → 401; токен есть, но объект чужой или не
существует → 404 (id нельзя перебирать). Протухший родительский токен не
мешает валидному токену ребёнка. Каталог миссий (`GET /api/missions[/{id}]`)
остаётся публичным.

Защита логина: `core/login_guard.py` — счётчики НЕУДАЧНЫХ попыток по паре
IP+email (5), по IP (20), по email (30) за 15 минут → `429` + `Retry-After`,
пока хоть один исчерпан; проверка идёт до bcrypt. Лимиты — в `Settings`
(`LOGIN_*`). Счётчики в памяти процесса (см. ограничения).

### Frontend (React + TypeScript + Vite, React Router, TanStack Query)

- **Состояние сессии** — `features/session` (`SessionProvider`,
  `useSession`). Один источник правды: активный ребёнок на устройстве
  (токен ребёнка, `localStorage: neuroquest.player_token`; игрок
  определяется через `GET /api/players/me`) и вошедший родитель
  (`neuroquest.parent_token`). `api/client.ts` шлёт оба заголовка. `usePlayer()` и `useAuth()` — тонкие обёртки.
  `signOutAll()` очищает оба. `api/client.ts` сам добавляет Bearer-токен.
- **Каркас** — `app/AppLayout`: липкая шапка с градиентом (логотип, «строка
  поиска» для ввода кода карточки, навигация, меню профиля справа), на
  телефонах нижняя таб-панель. Экран квеста — «immersive» (на всю высоту,
  без футера и таб-панели). `/finale` вне каркаса (полноэкранное шоу).
- **Меню профиля** (`features/layout/ProfileMenu`): аватар справа вверху,
  выпадает по клику; пункты — профиль, конверты, кабинет родителя,
  настройки, «Выйти», ссылки на документы. Закрывается кликом вне и Esc.
- **Дизайн-система** — `src/index.css`: токены (фирменный фиолетово-
  пурпурный градиент, светло-серый фон, белые скруглённые карточки),
  общие `.btn/.chip/.card/.input/.page/.back-link`. Стиль вдохновлён
  маркетплейсами; фирменные знаки/логотипы чужих брендов не копировались.
  Адаптив: `--gutter: clamp(14px, 3vw, 40px)`, контент на всю ширину
  (макс. 1600px), узкие колонки только там, где важна читаемость
  (чат 1180px, формы, документы, настройки).
- **Каталог миссий** (`pages/MissionsPage`): карточки «как товар» —
  цветная зона по цвету сектора с бейджем типа, жирная строка награды
  (аналог цены), «сектор / название», описание, тип проверки, кнопка;
  чипы-фильтры по секторам; 2 колонки на телефоне.
- **Ключевой принцип сохраняется:** `QuestChat` и `MissionFlow` —
  generic-компоненты, управляются JSON от API, ничего не знают о конкретных
  карточках. Новая карточка = новый YAML, без правок фронтенда.

Маршруты: `/` главная · `/quest/:sessionId` чат · `/missions` каталог ·
`/mission/:id` миссия · `/profile` достижения и мастер-код · `/finale`
гранд-финал · `/parent` вход или кабинет · `/review` проверка фото ·
`/settings` · `/terms` · `/privacy`. Ссылки из QR: `/?quest=<token>`
(автозапуск), от родителя: `/?t=<токен ребёнка>` (активирует профиль на устройстве и
стирает токен из адресной строки; старые `/?child=<id>` больше ничего не дают).

- **Реальный браузер:** `tools/browser-checks` — `smoke.mjs` (25 шагов

## Известные ограничения и открытые вопросы

1. **Юридические тексты — черновик**, не юридическая консультация. На
   страницах стоит предупреждение и плейсхолдеры `[Название организации]`,
   `[контактный email]`. Нужна проверка юристом (данные детей).
2. ~~Игровые эндпоинты не проверяют владельца~~ — **закрыто**: токен
   ребёнка + проверка владельца (см. «Доступ»). Остаётся: токен лежит в
   `localStorage` и в ссылке — кто получил ссылку, тот играет за ребёнка
   (лечится кнопкой «Сбросить доступ» в кабинете); существовавшие
   устройства со старым `neuroquest.player_id` нужно один раз заново
   подключить новой ссылкой.
3. Rate-limit логина хранится **в памяти процесса**: при нескольких
   воркерах/инстансах лимит умножается — для масштабирования вынести в
   Redis. За прокси запускать uvicorn с `--proxy-headers`
   (`--forwarded-allow-ips`), иначе все клиенты выглядят как один IP.
   Регистрация лимитом пока не закрыта.
4. `JWT_SECRET_KEY` в `.env.example` — dev-заглушка, обязательно сменить.
5. Цвета секторов (`color_token`) — мои плейсхолдеры: в исходнике цвета
   названы только словами. Заменить на значения дизайн-системы.
6. Приз гранд-финала — честная заглушка «скоро»: в исходнике раздел
   помечен автором как ИИ-черновик, реального промокода не выдумано.
7. Миссия 2 («Энигма») работает по присланным шифрам; готовность
   физического реквизита уточнить у владельца до печати.
8. Нет Dockerfile для backend/frontend, нет CI; `docker-compose.yml`
   поднимает только Postgres.
9. Лоадер контента не обновляет уже загруженное (см. выше).
10. Фото миссий хранятся в БД как base64 (`Text`) — для продакшена нужно
    файловое/объектное хранилище.
11. Каталог миссий сегодня не требует профиля ребёнка, а страница миссии
    требует — осознанно (смотреть можно, выполнять нельзя без профиля).

## Особенности песочницы Claude (экономят часы)

- Фоновые процессы **не переживают** между вызовами инструмента: сервер,
  Postgres и проверки надо запускать в одном вызове (удобно — bash-скрипт).
- `pkill -f слово` убивает и сам вызывающий шелл, если слово есть в команде:
  сохранять PID (`$!`) и делать `kill $PID`.
- Шелл инструмента — `sh` (dash): `${PIPESTATUS[0]}` и подобное падает —
  логику класть в файл с `#!/bin/bash`.
- Postgres: `apt-get install postgresql`, в каждом вызове
  `service postgresql start`; роль `neuroquest/neuroquest` (SUPERUSER), базы
  `neuroquest` и `neuroquest_test`. Docker недоступен.
- Сеть: github, npm, pypi, apt доступны; CDN Playwright закрыт, но
  `@sparticuz/chromium` (Chromium внутри npm-пакета) работает — на нём
  `tools/browser-checks`. Для эмодзи на скриншотах: `fonts-noto-color-emoji`.
- Chromium из этого пакета запускается с `--single-process` — в этом режиме
  падают изолированные контексты; `common.mjs` флаг убирает.
- `create_file` всегда требует параметр `path` и не перезаписывает файл.
- Git-автор: `KimDmitriyR <kdmitrikim@yandex.ru>`.

## Как мы работаем (продолжать)

  коммиты должны собираться.

- Игровой контент — только из присланных исходников; противоречия и
  пробелы фиксировать явно (комментарий в YAML + сообщение), не додумывать.
- Юридические вопросы — давать фактуру и черновик, прямо говорить, что это
  не консультация юриста.
