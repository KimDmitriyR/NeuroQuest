# Проверки в реальном браузере

Небольшой набор скриптов (puppeteer), которые открывают настоящий Chromium
и проверяют фронтенд так, как это делает человек: кликами. До их появления
интерфейс проверялся только сборкой и линтером.

| скрипт | что делает |
|---|---|
| `smoke.mjs` | сквозной сценарий: регистрация (с блокировкой без согласия) → добавить ребёнка → «играть на этом устройстве» → запуск квеста по коду → ответ и достижение → ошибка при неверном коде → фильтр миссий → меню профиля → выход → устройство ребёнка: вход по ссылке `/?t=…` без родителя, сброс доступа, старые `?child=` не работают |
| `overflow.mjs` | 11 страниц × ширины 360/390/768 × гость/вошёл + экран гранд-финала (после конца анимации, проверяется и правый край сертификата): падает, если что-то не помещается по ширине |
| `screenshots.mjs` | скриншоты всех экранов (десктоп 1440 и телефон 390) с реалистичными данными → `out/`; для гранд-финала сам создаёт ребёнка с 12 пройденными карточками (`finale-assembly-m`, `finale-hack-m`, `finale-cert-m`, `finale-cert-d`) |

Скрипты завершаются кодом `1`, если что-то не прошло (удобно для CI).

## Запуск

Нужны запущенные backend (`:8000`, с засеянным контентом) и frontend (`:5173`).
Для проверки «как у пользователя» лучше собрать и запустить продакшен-сборку:

```bash
# терминал 1 — backend
cd backend && uvicorn app.main:app --port 8000

# терминал 2 — frontend (порт именно 5173: на него настроен CORS)
cd frontend && npm run build && npx vite preview --port 5173 --strictPort

# терминал 3 — проверки
cd tools/browser-checks
npm install
npm run smoke
npm run overflow
npm run screenshots          # или: node screenshots.mjs home-m missions-d
```

### Какой браузер используется

- Если задана переменная `CHROME_PATH` — именно он. Windows, PowerShell:
  `$env:CHROME_PATH="C:\Program Files\Google\Chrome\Application\chrome.exe"`
- Иначе — Chromium, вложенный в пакет `@sparticuz/chromium` (работает в Linux-
  песочницах и CI без установленного браузера, ничего скачивать отдельно не нужно).

Адреса можно переопределить: `API_URL`, `WEB_URL`.

> Скрипты создают одноразовых родителей с адресами `check-…@example.com` —
> на проде их запускать не нужно, только на локальной/тестовой базе.
